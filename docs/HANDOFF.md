# 申し送り

セッションをまたいで引き継ぐ事項をここに書きます。**新しいものを上に**追加してください。

書くのは「次に触る人が知らないと困ること」だけです。完了した作業の記録は不要で、それは git log とコミットメッセージの役目です。ここに残すのは、コードを読んだだけでは分からない判断・未解決の疑問・意図的に見送ったことです。

片付いた項目は「解決済み」に移し、日付と結論を1行添えます。

各項目のテンプレート:

```markdown
## YYYY-MM-DD 見出し（何の話か一目で分かる短い名前）

**状況** — 何が起きているか。関係するファイルは `path/to/file.swift:42` の形で示します。
**なぜ未解決か** — 判断待ちなのか、作業量の問題なのか、確認手段がないのか。
**次にやること** — 判断が必要なら選択肢を並べます。作業が必要なら手順を書きます。
```

### 2026-07-27 文字サイズ 24pt にステッパーで戻れない

**状況** — [`EditorView.swift:5`](../EathWrit/EditorView.swift) の初期値が `24`、[`EditorView.swift:11-12`](../EathWrit/EditorView.swift) が範囲 `14...60`・刻み `4` です。`Stepper` は下限の 14 を基点に刻むため、実際に取れる値は 14 / 18 / 22 / 26 … となり、**24pt には初回起動時しか到達できません**。一度でも `+` か `−` を押すと二度と 24pt に戻せません。

スクリーンショット撮影時に気づきました。26pt になっていた端末を 24pt に戻せず、アプリを再インストールして `UserDefaults` を消す必要がありました。

**なぜ未解決か** — 意図した挙動か判断がついていません。実害は「初期値だけ他と揃わない」ことだけで、書く分には困りません。README / README_ja / llms.txt には「初期値 24pt、4pt 刻み」とだけ書いてあり、事実としては正しいので docs 側の修正は不要です。

**次にやること** — どれかを選ぶ。

1. 初期値を 22 か 26 に変える（刻みの上に乗せる。1行の変更で、既存ユーザーの保存値は影響を受けない）
2. 刻みを 2 にして 14〜60 を全部偶数で取れるようにする（タップ回数は倍になる）
3. そのままにする（初期値は「最初に見せたいサイズ」であって、刻みに乗る必要はないという整理）
