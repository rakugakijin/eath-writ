# AI 整形（音声入力の後始末）設計

日付: 2026-07-27

> **この設計は実装後に破棄した。結論は下の「改訂」を読むこと。**
> 以下の本文は当時の判断を残すためのもので、現在のコードとは一致しない。

## 目的

音声入力で書いた本文には誤変換・脱字・句読点の乱れ・フィラーが混じる。これを 1 タップで整える。

EathWrit の動線は「書く → Copy & Clear → 他アプリへ貼る」であり、推敲はその間に入る工程そのものである。書き終えた直後に整えてそのままコピーできる位置に置く。

## Writing Tools を使わない理由

`UIResponder.showWritingTools(_:)`（iOS 18.2+）は Apple 固定の UI を開くだけで、プリセットは校正・フレンドリー・プロフェッショナル・簡潔などに固定されている。自前の指示文を渡す API はない。iOS 18.2 以降は「変更内容を説明」の自由入力欄があるが、毎回手で打つ必要があり、事前登録もプリフィルもできない。

用途が「音声入力の後始末」に固定されている以上、指示文を保持できないことは致命的なので採用しない。

代わりに **FoundationModels**（iOS 26.0+）を使う。端末内 LLM に任意の instructions を直接渡せる。API キー不要、ネットワーク不要、課金なし。

## 前提

- 対象端末は iPhone 15 Pro（A17 Pro、Apple Intelligence 対応）
- deployment target を 17.0 から 26.0 へ引き上げる
- 自分専用アプリのため、非対応端末での動作は考慮しない

## 構成

### 1. `EathWrit/Polish.swift`（新規）

```swift
@MainActor enum Polisher {
    static var isAvailable: Bool
    static func polish(_ text: String) async throws -> String
}
```

- `isAvailable` は `SystemLanguageModel.default.availability == .available` を返す
- `polish` は `LanguageModelSession(instructions:)` を作り `respond(to: text)` を呼ぶ
- instructions は 1 プリセット固定:

  > 音声入力された日本語テキストの誤変換・脱字・句読点を直し、フィラー（「えーと」等）を除く。文体・語彙・情報は変えない。修正後の本文だけを出力する。

- 呼び出しごとにセッションを作る。会話履歴を持たせる必要がなく、前回の本文が次回に影響しては困るため

### 2. `EathWrit/PolishSheet.swift`（新規）

適用前プレビュー。本文を書き換える前に結果を確認し、採用可否を選ぶ。

- 状態は「実行中」「成功（結果あり）」「失敗（理由あり）」の 3 つ
- 実行中は `ProgressView`
- 成功時は結果本文をスクロール表示し、「整形後 / 元の文」の切り替えを置く。情報が落ちていないか見比べるためのもので、品質検証が主目的である本実装では中心的な要素
- 表示は `.body` 固定。エディタの `fontSize`（最大 60pt）を引き継ぐと一覧性が落ちるため
- 対象は常にバッファ全文。選択範囲は見ない。EathWrit が存在する理由は iPhone 上の選択操作が苦痛だからであり、AI に届くまでに選択ジェスチャーを要求するのは前提と矛盾する
- 「採用」で全文を置き換えて閉じる。「破棄」で本文に触れず閉じる
- 失敗時は理由を表示し、閉じるのみ

### 3. `EditorView` への追加

上部バーの trash の左に `wand.and.sparkles` ボタンを 1 つ。

下部バーではなく上部にする理由は既存コードのコメントの通りで、下部は「親指の一等地＝頻繁に押すもの」、上部は「親指が届きにくい＝誤タップさせたくないもの」。全文を書き換える操作は後者にあたる。

- 本文が空のときは disabled
- `Polisher.isAvailable` が false ならボタン自体を出さない
- タップで即座に sheet を提示し、実行はその中で行う。押してから無反応の時間を作らないため
- 採用時は「整形しました（Undoで戻せます）」をトースト表示

### 4. Undo は追加実装なし

`EditorController.replaceAll(with:)` は既に `UITextInput.replace` 経由で、Undo スタックに載る。AI の結果も既存の Undo ボタンでそのまま戻せる。ここには何も足さない。

## エラー時の扱い

いずれの失敗でも本文は書き換えない。sheet 内に理由を出して閉じるだけ。

- モデル利用不可
- コンテキスト長超過（長文時）
- ガードレールによる拒否
- その他

## 検証したいこと

この実装は以下を実機で確かめるためのものである。

- 日本語の整形品質。特に「直しすぎて元の意味を変えていないか」
- コンテキスト長エラーが出始める実際の分量

いずれも自分の音声入力テキストを流すまで分からない。結果次第でプリセットの追加や外部 API への切り替えを判断する。

## やらないこと

- 複数プリセット。1 つで品質を見てから決める
- Compose 相当（AI に生成させる）。貼り先が AI アプリなら輪が閉じない
- 要約・要点抽出。対象を先に貼り込む必要があり、書いて捨てるバッファという前提に合わない
- 非対応端末向けのフォールバック

## 改訂（2026-07-27、同日）

上記の設計で実装し（`fc9bca0`）、動かして破棄した。

### 何が起きたか

音声入力を模した日本語を流したところ、こうなった。

```
元:  えーと、明日の会議はあの十時からで、資料は事前に共有しときます。
     あと、先方の担当者が返るそうなので、その連絡も待ちです。

後:  明日の会議はあの10時からで、資料は事前に共有します。
     あと、先方の担当者が返るそうですので、その連絡も待ちます。
```

指示通りなのは「えーと、」の除去だけだった。

- 本来直したい誤変換（`返る`）は直らない
- 一方で指示していない書き換えをする（`共有しときます` → `共有します`、`なので` → `ですので`、`十時` → `10時`）
- instructions で「文体・語彙・言い回しは変えない」と明示しても従わない
- `待ちです` → `待ちます` のように意味がわずかにずれる

### なぜ設計が間違っていたか

出発点は「カスタムプロンプトを流せないと嬉しくない」という前提だった。その前提から Writing Tools を却下し、FoundationModels を選んだ。

しかし流せるようにしても結果は良くならなかった。**制御できることと、望む結果が得られることは別だった。** 端末内モデルの出力品質が律速で、指示の自由度はそこに効かない。

### 現在の設計

ボタンは「全文選択 → 作文ツール起動」の手数を省くだけのものにした。何をさせるかは Apple の UI 側で毎回選ぶ。

- `EditorController.showWritingTools()` が全文を選択して `UIResponder.showWritingTools(_:)`（iOS 18.2+）を呼ぶ
- カスタムプロンプトなし、プレビューなし、`Polish.swift` と `PolishSheet.swift` は削除
- deployment target は 17.0 に戻し、ボタンだけ `if #available(iOS 18.2, *)` で囲む

このアプリが存在する理由は iPhone 上の選択操作が苦痛だからで、肩代わりする価値があるのはそこだけだった。

### シミュレータでは動かない

実機 iPhone 15 Pro ではボタンを押すと作文ツールが開く。**動作は確認済み。**

一方シミュレータでは `canPerformAction(showWritingTools:)` が false を返し、パネルが開かない。first responder であること・全文が選択されていること・`writingToolsBehavior` を `.complete` にすることはいずれも確認済みで、それでも false になる。同じシミュレータで FoundationModels は動いていたので Apple Intelligence が丸ごと無効なわけではなく、作文ツールの UI だけが提供されていない。

**この機能をシミュレータで検証しようとしないこと。** 実機でしか確かめられない。
